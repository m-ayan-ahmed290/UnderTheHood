# Architecture, security and recovery

Android is a native Kotlin/Compose app. Room provides durable WAL SQLite metadata. WorkManager persists transfer and folder-backup jobs. SAF supplies explicit user storage grants. Argon2id uses 64 MiB memory, 3 passes, one lane and a random 16-byte salt for the local unlock verifier. Android Keystore AES-256/GCM protects application secrets. The local passphrase is not a database encryption key.

Rclone 1.75.2 is compiled from official Go module source verified by Go's checksum database. On ARM64 Android, `GOOS=android`, `CGO_ENABLED=0` produces a compatible executable. Packaging under `jniLibs/arm64-v8a/librclone.so` with legacy/extracted native packaging permits execution from the installation's native directory. It is an executable, not a JNI library, and must not be loaded with `System.loadLibrary`. Android and OEM process/background behavior still require device testing.

Android starts Rclone RC on a randomly selected loopback port, with a random Basic auth password passed in the process environment. Browser clients do not receive this privileged password. RC output remains in app-private cache. No tokens are deliberately logged by application code. Provider configuration is encrypted using Rclone's supported configuration encryption before adding accounts. OAuth is initiated by Rclone; browser login uses its loopback authorization endpoint. Blank client fields are omitted rather than stored as empty overrides. No universal guarantee of shared OAuth access is possible.

The Rust core stores virtual nodes separately from remote paths. Moves change metadata; imported objects remain where they were. SQLite uniqueness rejects sibling name collisions. Ancestor validation rejects folder cycles. Mutations append a transactional journal. Snapshot restore validates the complete tree in a staging database, then restores transactionally into an empty destination. Keep exported snapshots on separate storage. Provider credentials are excluded, and remotes must be reconnected with matching IDs after restoration. There is no automatic last-snapshot retention or remote manifest reconciliation yet.

The Rust chunk utility streams input using a configurable bounded buffer, hashes each piece and the complete file with SHA-256, flushes objects, and atomically commits the manifest. Reconstruction rejects traversal, verifies each chunk and the full file, and commits a temporary output without replacing existing destinations only on success. It is a local core utility; distributed chunk upload, encryption, redundant copies and garbage collection are not wired into the applications yet. Missing required objects make capacity-mode data unrecoverable. Never label planner output as an actual protected file.

Desktop starts a Rust companion in-process. The companion binds IPv4 loopback and validates Host against literal loopback authorities to reject DNS rebinding. Every API call requires a process-random Bearer token, including GETs. Origins are checked against the local app and one explicitly configured development/PWA origin; CORS uses an exact origin, never `*`. A hostile page cannot authenticate merely by reaching localhost. The static shell contains no privileged token. Pairing tokens are passed via URL fragments then retained in browser session storage. Same-origin XSS or compromised local processes remain outside this boundary. Current tokens last until companion process restart; per-browser revocation/session expiry is pending.

The companion exposes a narrow versioned API, not the Rclone RC API. Remote IDs and paths are validated; subprocesses use argument arrays, not shell interpolation. Uploads are streamed to a private temporary file and transferred through Rclone; temporary files are removed after success/failure. Provider config must be protected with OS account permissions; desktop keychain encryption remains a documented gap.

Supabase is optional and handles app accounts and metadata only. Every event is owned by `auth.uid()`, RLS is enabled, anonymous access revoked, and update is not granted. Cross-account authorization never depends on user-editable metadata. Client publishable keys are not secrets; service-role keys must never ship. Android refresh/session tokens use the local Keystore vault. Sync transmits filenames and physical references, not Rclone provider credentials. RLS is access control, not E2E encryption. Conflicts are surfaced as additional entries rather than silently overwriting local revisions. Device token revocation and full concurrent-edit semantics remain pending.

Supported preview behavior is delegated to installed Android apps. Office, PDF, archive and media capabilities depend on available viewers. No universal native preview claim is made. Web remote mode is only a client setting; this repository does not deploy a public storage server or expose loopback Rclone on the internet.
